# Web agent settings

W9b1 intentionally differs from desktop rule 13: settings controls show provenance
(reported, set here, or built in). Unknown values live in the collapsed
"Set without seeing the current value" disclosure. Built-ins are choices, never
claims about an unreadable current value. The web is an admin client in this fork,
an intentional extension of VISION.md's repo-browser scope.

Use the W7 draft, save bar and navigation guard. Await the owner's desktop ack;
relay acceptance alone is not a save. Only a fresh, single claiming desktop can
receive a targeted write. Until P1a/P1b, Effort, Nobody, model/provider clears,
runtime inheritance and command extras remain locked, even on a newer catalog.

Access warnings reuse respondToField.ts and desktop rule 11's exact copy: directly
under Anyone, after the named people picker for Specific people. Unknown backend
uses local wording. Provider/API-key controls are only for Buzz Agent and Goose;
an unknown runtime exposes no inferred provider control.

API keys stay in transient form state and the sealed envVarsPatch. Never place
them in receipts, drafts, storage or logs. The browser's reload echo whitelists
only its own acknowledged idle/longest-duration edits, scoped by owner, relay,
agent and machine; it is not reported/decrypted desktop state. Undo is offered
only when the original value and its write path are known.
